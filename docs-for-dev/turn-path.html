One turn, end to end

A message arrives on a socket. Eleven capabilities compete to answer it. Six services assemble its context. Hundreds of events fly back out. Here is exactly which file does what, in what order, and where the sharp edges are.

01 The short version

If you read nothing else, read this.

Every entry point — CLI, WebSocket, Python SDK — calls the same function first: TurnApplicationService.start_turn. That service is the only writer of turn state. It creates a durable row, takes a lease, and spawns a task.

The task builds a UnifiedContext, hands it to TurnEngine, which hands it to ChatOrchestrator, which picks a capability by name. The capability runs and emits StreamEvent objects into a per-turn StreamBus.

The bus is the seam. The orchestrator writes into it. Adapters read out of it. Nothing else couples the two sides. Events persist as they are published, so a reconnecting client replays from a sequence number instead of starting over.

Three entry points

WebSocket /ws, Typer CLI, SDK facade. All three call the same application service.

02 The spine, in one picture

Read top to bottom. The solid arrows are the call path. The dashed line is the event path coming back.

Two things sit outside the spine. Coordination owns leases, commands, and the event journal. The session store owns conversations, messages, and turn rows. The application service touches both. Capabilities touch neither.

04 Life of one turn

Nine steps. Dots in the accent colour are the ones that bite when you get them wrong.

  1. 1 · Frame arrives The socket authenticates, parses the command, and forwards it. No state changes here. unified_ws.py → send_command_ack
  2. 2 · Submission reserved A SHA-256 digest of the payload, minus session and workspace, becomes the idempotency key. Send the same key twice and you get the same turn back. app/service.py · _submission_digest
  3. 3 · Lease taken One worker owns the turn. A second worker asking for the same session gets a conflict, not a second run. coordination · get_lease / submit_command
  4. 4 · Turn row written Queued, then running. This row is what a reconnecting client reads. services/session/sqlite_store.py (4,921)
  5. 5 · Context assembled History, knowledge base seeds, memory, personas, attachments, source index, workspace scope. Six services cooperate. The result is one dataclass. turns/executor.py · _run_turn
  6. 6 · Capability runs in its own task The orchestrator creates a task and subscribes to the bus. If the reader walks away, the turn keeps running until the finally block cancels it. runtime/orchestrator.py · asyncio.create_task
  7. 7 · Events stream out Each event gets a sequence number, persists, and fans out to every subscriber on that turn. runtime/stream_bus.py · emit
  8. 8 · Done, but not over A terminal done carries status and a usage summary. The session-title model still writes after it. That is why the stream stays open. orchestrator · finally → DONE
  9. 9 · Lease released, stream closes Releasing the lease is the honest end-of-stream signal. Subscribers exit because ownership disappeared, not because a timer expired. app/service.py · subscribe_turn
Why the turn runs in a separate task

A consumer can stop reading: a cancelled turn, a closed socket, a client that navigated away. If the capability ran inline, that would cancel the work and the row would sit in a live state forever.

Running it in a task lets the turn finish its own cleanup. The orchestrator's finally cancels the task only when the consumer stopped early, so the lease always gets released.

Why the same submission cannot start two turns

The digest excludes session_id and workspace_id. Everything else in the payload counts, including the tools, the knowledge bases, and the model choice.

On admission the store binds the submission to the turn it produced. A retry with the same key returns that turn. A retry with a different payload under the same key is refused.

05 Events and replay

This is the part that makes the system feel instant to a user and resilient to a restart.

One dataclass carries every message. Fifteen types cover thinking, tool calls, tool results, progress, sources, content, errors, and the terminal states.

core/stream.py72 lines
@dataclass
class StreamEvent:
    type: StreamEventType      # content, tool_call, done, …
    source: str = ""           # which capability emitted it
    stage: str = ""            # pipeline stage inside that capability
    content: str = ""          # human-readable text
    metadata: dict = {}        # structured payload
    session_id: str = ""
    turn_id: str = ""
    seq: int = 0               # monotonic per turn
    timestamp: float = …

The bus is a fan-out, not a queue

A StreamBus is created per turn. Producers call emit. Every subscriber gets its own queue, so a slow reader never blocks the capability. The bus keeps history, which is what makes late subscription work.

Buses also register by turn_id. That is how a second client attaches to a turn that is already running in a different task, without asking the capability to replay anything.

Durable replay

Events are committed to the store with their sequence number. A process restart loses nothing.

Live tail

The coordinator reads events past the last seen sequence, then waits for a notification.

The replay loop, in words

One. Read every stored event after after_seq. Track the highest sequence seen.

Two. Read live events from the coordinator past that sequence. If there are none and the lease is gone, re-read the store, because the in-memory stream may have been reclaimed while the subscriber was paused.

Three. After a done, keep reading. The tail is possible while the lease exists. A thirty-second cap exists only for a leaked lease.

Four. If the turn row says completed while the lease is still held, sleep briefly and re-check. Completion can commit before the owner publishes done.

What a failed turn looks like on the wire

Every failure path emits an error event with turn_terminal: true, then a done with the same status. The orchestrator copies error_code, retryable, and partial_response onto the terminal event when the exception carries them.

A capability that returns without publishing a result is not a success. The orchestrator reports capability_incomplete and marks the turn retryable.

06 Two loops, one name

This is the single most common misreading of the codebase.

There are two different agent loops. They share a vocabulary and nothing else.

Native tool calling chat

A round with tool_calls is a tool round. A round without them finishes the turn. The model is never asked to emit a label. Chat, mastery, reading, and course study run here.

agents/loop/pipeline.py (2,163)

Label protocol research

The reply must start with one allowed label in double backticks. The parser reads it, then routes the rest. Used by research, question generation, and PageIndex reasoning.

runtime/agentic/labeled_step.py (675)

Chat used to speak labels. It stopped in commit 46093e5e. If you are reading an older write-up and it tells you chat emits THINK and TOOL, that write-up is out of date.

The one thing that survives from the old protocol is thinking in the content channel. Chat splits <think> blocks off the stream as it arrives, so the user sees answer text and not reasoning.

Why chat's capability file is seventeen lines

Because chat is the default loop. AgenticChatPipeline subclasses the base pipeline and overrides nothing. All the behaviour — the exploring protocol, the tool surface, the prompt pack — lives in the base class.

Deep modes that keep chat's protocol construct that class directly and pass different budgets. A mode that needs a different protocol subclasses the host instead.

07 Traps

Each one is documented in the source by whoever hit it. They are the fastest way to stop guessing.

A done event is not the end of the stream

The session-title model writes after the answer is saved. Subscribers that return on done drop that event. A finished conversation then sits on "New conversation" forever, because the title frame never arrives.

app/service.py · _POST_DONE_MAX_SECONDS = 30.0

End of stream is a lease check, not a timeout

The turn task releases its lease inside its own finally, after every post-turn event is published. Waiting for an idle timeout must exceed the title model's own twenty-second ceiling, which holds every finished stream open for twenty seconds when no title was written.

app/service.py · subscribe_turn

Stopping the reader does not stop the run

The capability runs in its own task. Left alone, it keeps calling the model and tools for a turn already reported as stopped. Left parked on ask_user, it gets collected mid-await and never unregisters its bus.

runtime/orchestrator.py · finally

Returning without a result counts as failure

The bus records whether a result was published. If a capability returns without one, the turn is marked capability_incomplete with retryable: true. Silence is not success.

orchestrator.py · bus.result_completion

Declared tools are not mounted tools

A capability can name a tool in its manifest and still get nothing. The gate decides. A knowledge base tool without a knowledge base never mounts. Nineteen tools are conditional this way.

agents/_shared/tool_composition.py · _CONDITIONAL_MOUNT_FLAGS

Absent fields must not overwrite inherited preferences

Admission resolves defaults and durable choices. Writing the transport envelope back over the session would blank a preference the user set two turns ago and never resent.

app/service.py · update_session_preferences

Old sources stay attached on purpose

Source references accumulate into workspace_dependencies. A turn that no longer selects a knowledge base still keeps it listed, so citations from earlier answers keep resolving.

app/service.py · workspace_dependencies

Physical paths never enter the model

The workspace carries real filesystem roots. The rule in the dataclass is explicit: those paths must never be copied into model messages, persisted metadata, or public URLs.

core/context.py · WorkspaceRuntimeContext

An unknown capability is not an exception

It produces an error event listing the available names, then a terminal done. A caller sees a normal failed turn, not a crash.

orchestrator.py · capability is None

The compatibility module lies about its size

turn_runtime.py is fifty-five lines. The behaviour is 1,806 lines away in _turn_runtime_shared.py, forwarded by a module-level __getattr__. Jump to definition and you land on a stub.

Each one names the files. Claude reads the real code instead of guessing from names. Each one names the reader. "Someone reading it once" is a different page from "someone maintaining it".
